# 工作日节点流程 v2.1.0

每个节点互相独立。先读取 `prompts/global_policy.md`、`prompts/data_acquisition.md`、账户上下文、活动策略和当前候选池；上一个节点缺失不影响当前节点，不补发过期指令。

## 通用盘中流程

1. 检查未反馈委托；任何当日首个实际执行的节点发现账户 `as_of` 早于当前交易日且无未反馈委托时，必须立即调用 `trading_day_rollover`，不得依赖09:08节点已经运行，也不得在滚动前判断T+1或可卖数量。
2. 由 Agent 按数据采集协议分类获取主要指数、市场广度和相关板块状态；仅对持仓和候选池股票获取实时行情、K线、公告及增量消息。不得运行单体行情聚合脚本。
3. 对持仓计算固定止损、两级止盈、移动止盈、支撑压力、T+1和可做T数量；对候选检查入场门槛和相对持仓优势。
4. T+2仅重试失败类别并切换独立来源；T+4刷新全部持仓和候选最新价。单类失败不阻断其他类别和归档；报价冲突、过期或不足两源时不生成订单。
5. 检查候选池健康；达到触发条件时记录 `watch`、`frozen` 或 `invalidated`。盘中不全市场重筛。
6. 有操作时先登记订单意图；无操作时明确“本时点没有创建任何订单”。无论数据是否完整，必须在任务时限内记录本次分析。

## 节点差异

- 09:08：盘前准备，不创建订单。核验交易日、跨日滚动、未反馈委托、隔夜及新增公告、候选池有效期和周末变化，形成当日风险预案。
- 09:22：分析集合竞价和板块竞价强弱；09:26最后刷新，只允许生成09:27-09:32指令。
- 10:30：判断开盘后量价确认、假突破和持仓/候选相对强弱；10:34刷新，只允许生成10:35-10:40指令。
- 11:25：总结上午趋势和午间风险；11:29刷新。达到或超过11:30时只记录、不生成订单，并使用最小证据集在180秒采集预算内完成，禁止继续等待非关键数据。
- 13:00：核验午间公告和下午开盘状态；13:04刷新，只允许生成13:05-13:10指令。
- 14:25：判断尾盘趋势是否确认；14:29刷新，只允许生成14:30-14:35指令。
- 14:50：处理隔夜风险和当日最后可执行计划；14:54刷新，只允许生成14:55-15:00指令。
- 15:05：不生成当日订单。使用收盘数据完成持仓和候选复盘、候选池健康判定、账户及未反馈委托核对、日报/周报/月报归档。候选池为 `invalidated` 时按周筛流程执行盘后应急重筛，新池次日09:08核验后生效。

## 用户输出

写明分析时点和最后行情刷新时间、数据源健康、市场和板块结论、每只持仓与候选的动作结论。存在订单时按全局协议给出精确指令；不存在订单时明确说明原因和下一失效/观察条件。
