# Agent 数据采集协议 v2.2.0

本协议用于明确“数据由 Agent 获取”的含义：Agent 负责按数据类别规划、调用、重试、切换来源和判断可用性；项目中不存在必须成功的行情聚合程序。

## 调用边界

- Agent 可以调用网页检索、公开页面、数据技能、API适配脚本和技术指标工具，但这些都只是可替换的数据适配器。
- 禁止新建或调用把指数、板块、全部个股、K线、公告和新闻捆绑成一次执行的单体行情聚合脚本。
- 禁止把任一脚本、技能或站点成功作为节点继续运行的前置条件。
- `a-share-data` 中的脚本只可按单一数据类别调用；其“优先脚本”说明不覆盖本协议的分类取数、限时和降级规则。
- 在PowerShell中调用逗号分隔的批量股票代码参数时，必须把整个参数值放在引号内，防止 `000001` 等代码被解析为数字并丢失前导零。
- 项目 MCP 不提供行情事实，只保存账户、候选池、策略检查、订单意图和审计记录。

## 日内分类取数

按下列顺序分别处理，每类独立成功或失败：

1. 指数与市场广度：获取上证指数、深证成指、沪深300及可核验的涨跌家数。
2. 相关板块：只获取持仓与候选所属板块的涨跌、广度和成交状态。
3. 实时报价：一次批量获取持仓与候选，最多7只。腾讯为主源；若返回全部所需标的的完整、新鲜报价，立即结束实时报价采集，不再调用其他报价源。仅主源失败、个别标的缺失、字段异常或过期时，才对受影响标的调用独立备用源。
4. 历史K线与技术指标：优先复用当日已有有效结果，仅增量更新；不得因某个周期缺失阻断节点。
5. 公告与新闻：公司公告、交易所和巨潮资讯优先；网页检索仅补充权威媒体增量信息。

非交易节点或已经错过执行窗口时，允许使用最小证据集：主要指数、持仓与候选最新价、相关板块、当日新增公告。不得为了补齐非关键指标耗尽任务时限。

## 限时与降级

- 单个来源一次调用最多等待45秒；明确支持批量且有部分结果返回的调用最多75秒。
- 同一来源最多重试一次；仅当剩余采集预算不少于90秒时才允许重试，否则立即切换独立备用源。
- 日内节点数据采集总预算为240秒；11:25节点在11:30后启动时总预算为180秒。
- 至少保留75秒用于分析、候选池健康判断和 `analysis_run_record`。
- 一个类别全部来源失败，只把该类别标记为不可用并继续其他类别。不得输出“聚合脚本失败，因此节点结束”。
- 每个节点的关键实时报价必须在本节点开始后重新采集。前序节点的成功报价可作比较基准，但超过90秒不得用于下单。
- 当前节点主报价源合规时不得调用备用报价源。仅主源失败、缺失、字段异常或过期时才实际调用独立备用源；只有当前节点的调用结果才能写成“备用源不可用”。
- 一个可识别、字段完整且不超过90秒的合规实时报价源即可创建订单，不得仅因没有第二来源而拒绝精确指令。
- 所有来源均不可用时，也必须记录尝试过的来源、错误、时间和“本时点没有创建任何订单”。

## 输出要求

数据健康按类别列出来源、采集时间、数据时间、状态和失败摘要。不得使用“行情聚合脚本”这类无法识别真实来源的笼统表述。用户看到的应是具体来源及降级结果，例如“腾讯报价超时，已切换新浪；公告使用巨潮资讯”。
